# Tolkien — Definitions & Reference

> **Language / Idioma:** English | [Versão em Português](pt-BR/DEFINITIONS.md)

Complete glossary, agent inventory, skill catalog, and directory specification for the Academic Article Production Multi-Agent System.

---

## Glossary

| Term | Definition |
|------|-----------|
| **Academic SDD** | Spec-Driven Development adapted for scientific writing. Enforces strict sequencing: PRD → Plan → Execution. No phase may start before the previous one is validated. |
| **Agent** | A high-level coordinator that orchestrates multiple skills to achieve a complex, multi-step goal (e.g., running the full literature research pipeline). Agents can be invoked by trigger phrases in Claude Code, OpenCode, Codex, or Antigravity. |
| **Skill** | An atomic, single-purpose capability that performs one specific task (e.g., searching OpenAlex, compiling LaTeX, checking AI markers). Skills are invoked via `/skill-name` commands. |
| **Gate** | A mandatory checkpoint that blocks pipeline progression until defined quality criteria are met. Gates: G1, G2, G3, G4 (Citation↔Bibliography), **G4.5 (Data Integrity)**, G5 (Final 6-D Review), and the **Output Format Gate** (md/tex/docx). |
| **PRD** | Product Requirements Document — in this context, the academic paper specification. Defines research questions, target venue, citation style, language, and constraints. Stored as `prd.md`. |
| **prd.md** | The paper requirements file generated by `academic-prd`. It is the single source of truth for all pipeline decisions. |
| **plan.md** | The implementation roadmap generated by `academic-plan` from `prd.md`. Lists all 9+ phases with tasks, deliverables, and acceptance criteria. |
| **references.bib** | The BibTeX bibliography file. Managed by `academic-bibliography-manager`. Used as the sole source of citations by `academic-citation-manager`. |
| **Scope Card** | Mandatory metadata comment (`<!-- SCOPE_CARD ... -->`) placed at the top of every section draft, defining the strict Level of Analysis, Primary Question, Out-of-Scope boundaries, and Theoretical Anchor. Prevents level-of-analysis confusion and scope drift. |
| **CEI Architecture** | Claim → Evidence → Interpretation structural discipline for substantive academic paragraphs, ensuring claims are immediately backed by empirical evidence and interpreted with causal mechanisms. |
| **6 Motivation Triggers** | Mandatory inflection points where the text must causally explain "why": (1) Architectural Design, (2) Counter-intuitive Result, (3) Technical/Economic Trade-off, (4) Literature Divergence, (5) Scope Limit Invocation, (6) Conceptual Borrowing/Metaphor. |
| **Continuous Revision Loop** | Automated feedback loop across Phases 5–7 (*write → validate (G4, G4.5) → 6-D review (G5) → rewrite/correct → re-review*), repeating until Complete Approval is reached. |
| **Writing Quality Audit** | Deterministic pre-review audit executed by `academic-writing-reviewer` checking AI markers (`AIM`), repetition/echoes (`REP`), metric tensions (`NUM`), and unglossed computing jargon (`JAR-01`). Feeds Dimension 5 of the 6-D review. |
| **IMRaD** | Introduction, Methods, Results, and Discussion — the standard structure for empirical research papers. |
| **6-D Review** | The six-dimension peer review run by `academic-reviewer` (0–100 scale): (1) Scientific Rigor & Methodology (25%), (2) Data & Results Integrity (20%), (3) Originality & Contribution (15%), (4) Argument & Evidence Coherence (15%), (5) Writing Quality (15%), (6) Format & Bibliographic Compliance (10%). Simulated by a 5-persona panel: EIC + R1 Methodology + R2 Domain + R3 Perspective + Devil's Advocate. |
| **Data Integrity Gate (G4.5)** | The deterministic gate run by `academic-data-validator`/`data-validation-agent` validating congruence of the text with the data presented: numbers in prose vs tables/figures, internal numeric consistency (Ns, totals, %), and two-way Table/Figure reference integrity. Feeds Dimension 2. |
| **Output Format Gate** | The always-on gate run by `academic-format-validator`/`format-validation-agent` validating document formatting across Markdown, LaTeX and Word (.docx). Reuses the `latex` and `docx` validators. Feeds Dimension 6. Enforced via a hook in every harness. |
| **process-record.md** | The human-AI collaboration log generated in Phase 9. Documents every decision, gate outcome, and revision during the pipeline run. |
| **OpenAlex** | Free, open scholarly database used by `academic-researcher` and `academic-bibliography-manager` to search literature and enrich BibTeX entries. No API key required. |
| **Citation↔Bibliography Gate (G4)** | The G4 validation that checks: (1) every in-text citation (LaTeX `\cite` or Harvard parenthetical) has a matching entry in `references.bib`; (2) every entry in `references.bib` is cited in the draft; (3) every `.bib` entry has all mandatory fields. |
| **Slug** | A short, URL-safe identifier for a paper project (e.g., `vector-retrieval`). Used as the directory name: `paper-{slug}/`. |
| **TinyTeX** | A lightweight LaTeX distribution installed by `install_skills_deps.sh` when a full TeX distribution is not found. Provides `pdflatex`, `bibtex`, and `tlmgr`. |
| **.venv** | The project-local Python virtual environment created at the repository root by `install_skills_deps.sh`. Must be activated before running any Python-based skill. |

## Agents

tolkien includes 8 specialized agents. All agent definitions are maintained across `.agents/agents/` (canonical), `.claude/agents/` (Claude Code), `.codex/agents/` (OpenAI Codex), and `.opencode/agents/` (OpenCode).

### academic-orchestrator

| Property | Value |
|----------|-------|
| **Purpose** | Master coordinator. Executes the full 10-phase pipeline, enforces gates, manages checkpoints, and drives the Continuous Revision Loop. |
| **Triggers** | `/academic-orchestrator`, `"start academic pipeline"`, `"write full article"`, `"academic pipeline"`, `/status` |
| **Dispatches** | All pipeline agents and skills, in order |
| **File** | `.agents/agents/academic-orchestrator.md` / `.claude/agents/academic-orchestrator.md` |

### research-agent

| Property | Value |
|----------|-------|
| **Purpose** | Systematic literature search, source triage, and bibliography synthesis. |
| **Triggers** | `/research-agent`, `"research for paper"`, `"search literature and validate bib"` |
| **Dispatches** | `academic-researcher`, `academic-bibliography-manager`, `web-browser-search-agent` |
| **File** | `.agents/agents/research-agent.md` / `.claude/agents/research-agent.md` |

### writing-agent

| Property | Value |
|----------|-------|
| **Purpose** | Full-text section drafting (Scope Cards & CEI), scientific media generation, register humanization (local/global passes), and pre-review writing audit. |
| **Triggers** | `/writing-agent`, `"draft full article"`, `"write and humanize"`, `"write section"` |
| **Dispatches** | `academic-writer`, `academic-media`, `academic-humanizer`, `academic-writing-reviewer` |
| **File** | `.agents/agents/writing-agent.md` / `.claude/agents/writing-agent.md` |

### review-agent

| Property | Value |
|----------|-------|
| **Purpose** | Citation↔Bibliography validation (G4), Data Integrity gate (G4.5), writing audit integration, and 6-dimension peer review with re-review cycles. |
| **Triggers** | `/review-agent`, `"review full article"`, `"execute academic review"`, `"verify citations"` |
| **Dispatches** | `academic-citation-manager`, `academic-bibliography-manager`, `academic-data-validator`, `academic-writing-reviewer`, `academic-reviewer`, `web-browser-search-agent` |
| **File** | `.agents/agents/review-agent.md` / `.claude/agents/review-agent.md` |

### data-validation-agent

| Property | Value |
|----------|-------|
| **Purpose** | Deterministic Data Integrity Gate (G4.5): validates congruence of text with data presented (numbers in prose vs tables/figures, float integrity, table arithmetic). |
| **Triggers** | `/data-validation-agent`, `"validate data congruence"`, `"check data integrity"` |
| **Dispatches** | `academic-data-validator`, `academic-media` |
| **File** | `.agents/agents/data-validation-agent.md` / `.claude/agents/data-validation-agent.md` |

### format-validation-agent

| Property | Value |
|----------|-------|
| **Purpose** | Always-on Output Format Gate: validates formatting across Markdown, LaTeX (.tex), and Word (.docx) deliverables. |
| **Triggers** | `/format-validation-agent`, `"validate formatting"`, `"check format"`, `"validate docx"` |
| **Dispatches** | `academic-format-validator`, `latex`, `docx` |
| **File** | `.agents/agents/format-validation-agent.md` / `.claude/agents/format-validation-agent.md` |

### paper-generator-agent

| Property | Value |
|----------|-------|
| **Purpose** | Converts the reviewed draft into a finalized PDF or DOCX using LaTeX or Word. |
| **Triggers** | `/paper-generator`, `"generate final paper"`, `"compile LaTeX"`, `"generate paper PDF"`, `"export paper"` |
| **Dispatches** | `latex`, `latex-template-converter`, `pdf`, `docx`, `academic-format-validator` |
| **File** | `.agents/agents/paper-generator-agent.md` / `.claude/agents/paper-generator-agent.md` |

### web-browser-search-agent

| Property | Value |
|----------|-------|
| **Purpose** | Web search and browser automation for grey literature, full-text retrieval, DOI resolution, and retraction checks. |
| **Triggers** | Invoked internally by `research-agent` and `review-agent`; also: `/web-browser-search-agent`, `"search the web"`, `"browse URL"`, `"validate DOI online"`, `"check URL"`, `"open website"`, `"extract web content"` |
| **Dispatches** | `web-browser-search`, `duckducksearch`, `agent-browser`, `playwright-cli` |
| **File** | `.agents/agents/web-browser-search-agent.md` / `.claude/agents/web-browser-search-agent.md` |

## Skills Inventory

tolkien includes **24 skills** (12 pipeline skills + 12 tool skills). All skill definitions live canonically under `.agents/skills/` and are mirrored under `.claude/skills/`.

### Pipeline Skills (12)

These skills implement the academic writing workflow.

| Skill | Trigger | Purpose | Pipeline Phase |
|-------|---------|---------|---------------|
| `academic-prd` | `/academic-prd` | Structured interview to generate `prd.md` | Phase 0 |
| `academic-plan` | `/academic-plan` | Generates `plan.md` from an approved PRD | Phase 1 |
| `academic-researcher` | `/academic-researcher` | Systematic literature search via OpenAlex API; produces `literature.md` and `references.bib` | Phase 2 |
| `academic-writer` | `/academic-writer`, `"write section"` | Drafts paper sections in IMRaD or thematic format with field-specific register, Scope Cards, and CEI architecture | Phase 3–4 |
| `academic-citation-manager` | `/academic-citation-manager`, `"verify citations"` | Validates in-text citations (LaTeX and Harvard parenthetical) against `references.bib` (Gate G4) | Phase 5 |
| `academic-bibliography-manager` | `/academic-bibliography-manager`, `"validate bibliography"` | Validates, deduplicates, and enriches `references.bib` via OpenAlex | Phase 5 |
| `academic-data-validator` | `/academic-data-validator`, `"validate data congruence"` | Data Integrity Gate (G4.5): validates congruence between prose numbers and tables/figures, float two-way integrity, and table arithmetic | Phase 5.5 |
| `academic-format-validator` | `/academic-format-validator`, `"validate formatting"` | Always-on Output Format Gate: validates Markdown, LaTeX (.tex), and Word (.docx) | Phase 8 |
| `academic-writing-reviewer` | `/academic-writing-reviewer`, `"audit writing"` | Read-only writing quality auditor checking AI markers (`AIM`), repetition (`REP`), metric tensions (`NUM`), and unglossed jargon (`JAR`); feeds Dimension 5 | Phase 6–7 |
| `academic-reviewer` | `/academic-reviewer`, `"review article"` | Simulates a 6-D review by a 5-persona panel: EIC + 3 domain reviewers + Devil's Advocate | Phase 7 |
| `academic-humanizer` | `/academic-humanizer`, `"humanize"` | Adjusts register and removes AI-writing markers via local and global passes. Supports EN and PT-BR. | Phase 6 |
| `academic-media` | `/academic-media`, `"create figure"` | Generates publication-quality figures, schematics, and exploratory data analysis (EDA) plots | Phase 4, 8 |

### Tool Skills (12)

These skills handle document formats and external system integration.

| Skill | Trigger | Purpose |
|-------|---------|---------|
| `latex` | `/latex` | Full LaTeX compilation, formatting, and error resolution |
| `latex-template-converter` | `/latex-template-converter` | Adapts documents to conference-specific LaTeX templates (ACM, IEEE, NeurIPS, SBBD, etc.) |
| `pdf` | `/pdf` | PDF text/table extraction, merging, splitting, watermarking, and creation |
| `docx` | `/docx` | Word document creation, editing, and formatting |
| `xlsx` | `/xlsx` | Spreadsheet reading, editing, and formula computation |
| `agent-browser` | `/agent-browser` | Browser automation: navigate, fill forms, click, screenshot, extract data |
| `playwright-cli` | `/playwright-cli` | Playwright-based browser testing and automation |
| `web-search` | `/web-search` | Web search returning ranked results with snippets and URLs |
| `web-browser-search` | `/web-browser-search` | Unified DuckDuckGo/Brave search + browser navigation |
| `duckducksearch` | `/duckducksearch` | DuckDuckGo search with image, video, and news filters |
| `creating-skills` | `/creating-skills` | Framework for developing, validating, and deploying new skills |
| `multi-ide-artifacts` | `/multi-ide-artifacts` | Converts agent artifacts across Claude Code, OpenCode, Codex, and other IDEs |

## Project Directory Structure

Each paper project must follow this structure exactly. The `output/` directory contains all final deliverables.

```text
{root}/paper-{slug}/
├── prd.md                     # Paper requirements (generated by academic-prd)
├── plan.md                    # Implementation roadmap (generated by academic-plan)
├── process-record.md          # AI-human collaboration log (generated in Phase 9)
│
├── resources/                 # (OPTIONAL) Paper governance and base files
│   ├── style-guide.md         # Author voice, register, and CEI rules
│   ├── anti-style-guide.md    # Banned clichés, AI markers, and tone flaws
│   └── human-decisions.md     # Author methodological and framing decisions
│
├── research/
│   ├── literature.md          # Annotated sources + synthesis
│   ├── search-strategy.md     # Documented search methodology (databases, queries)
│   └── references.bib         # BibTeX bibliography — source of truth for citations
│
├── draft/
│   ├── outline.md             # Approved structure + word count allocation
│   ├── 00-abstract.md         # Draft sections with Scope Cards and CEI paragraphs
│   ├── 01-introduction.md
│   ├── 02-theory.md
│   ├── 03-methodology.md
│   ├── 04-findings.md
│   ├── 05-discussion.md
│   ├── 06-conclusion.md
│   ├── 07-tables.md
│   └── 08-figure-legends.md
│
├── review/
│   ├── citation-report.md     # Gate G4: Citation↔Bibliography validation report
│   ├── data-congruence-report.md # Gate G4.5: Data integrity & float congruence report
│   ├── writing-review-report.md  # Writing quality audit (AIM, REP, NUM, JAR)
│   ├── review-report.md       # 6-D peer review results, scores, and Roadmap
│   ├── format-validation-report.md # Output Format Gate report
│   └── revision-log.md        # Revision history with rationale
│
└── output/                    # ALL final deliverables go here
    ├── paper.tex
    ├── paper.pdf
    ├── paper.docx
    └── figures/
```

**Valid root directories:**
```
projects/      papers/      .projects/      .papers/
```

Example full path: `/path/to/tolkien/papers/paper-vector-retrieval/`

## Multi-IDE Configuration Directories

tolkien is configured across the following directories for cross-IDE compatibility:

| Directory | Target IDE / Platform | Contents |
|-----------|-----------------------|----------|
| `.agents/` | OpenAI Codex, OpenCode, Google Antigravity | Canonical `agents/` (.md) and `skills/` (.md, scripts, references) |
| `.claude/` | Claude Code (CLI) | Mirror `agents/` (.md), `skills/`, and `settings.json` hooks |
| `.codex/` | OpenAI Codex | Harness `agents/*.toml` descriptors and `hooks.json` lifecycle hooks |
| `.opencode/` | OpenCode | Harness `agents/*.md` descriptors and `plugins/format-validator.js` |
| Root | All platforms | `AGENTS.md` (canonical baseline rules) and `CLAUDE.md` (Claude Code root instructions) |

### Python Environment

The `.venv/` directory at the repository root is the shared Python environment for all Python-based skills. It must be activated before invoking any skill that uses Python directly:

```bash
# Activate
source .venv/bin/activate

# Deactivate when done
deactivate
```
